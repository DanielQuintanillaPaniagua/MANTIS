## 1. Objetivo del hito

Dotar a MANTIS de un cliente HTTP controlado que pueda:

- enviar peticiones a APIs autorizadas,
- respetar límites de ejecución (timeouts, rate limits),
- registrar evidencia de cada petición/respuesta.

**MK-003 es infraestructura, no inteligencia.** No detecta vulnerabilidades.
Construye el músculo que MK-005 usará para detectar.

## 6. Formato de evidencia

Cada petición genera **una línea** de JSON en `logs/requests.jsonl`:

```json
{
  "timestamp": "2026-10-25T12:00:00Z",
  "method": "GET",
  "url": "http://127.0.0.1:8000/health",
  "status": 200,
  "duration_ms": 12.5,
  "request_headers": {},
  "response_headers": {"content-type": "application/json"},
  "response_size": 15,
  "error": null
}
Convenciones:

status = 0 cuando hubo error de red (timeout, connection refused, DNS).

error = null en éxito, <Tipo>: <mensaje> en fallo.

Una línea = un JSON. Sin comas. Sin [ ].

Esto hace el log parseable con jq, grep, awk, y no requiere cargar todo en memoria.

7. Comportamiento del cliente
Límites
Límite	Config	Cuándo se aplica
max_requests	Sesión completa	Al superar N peticiones en una sesión, RateLimitExceeded
requests_per_minute	Ventana deslizante de 60s	Al superar N peticiones en 60s, RateLimitExceeded
timeout_seconds	Por petición	Pasa a httpx.Client(timeout=...)
Orden de verificación: primero max_requests (contador absoluto), luego requests_per_minute (ventana). Si falla uno, no se consume del otro.

Errores
Error de red (httpx.HTTPError) → se loguea con status=0, error=<tipo> y se relanza. El llamador decide qué hacer.

Rate limit (RateLimitExceeded) → no se loguea como petición (no hubo petición HTTP real). Se relanza.

Redirects
follow_redirects=False por defecto. En un scanner, seguir redirects puede ocultar comportamiento. Se valorará configurabilidad en MK-004+.

8. Comando CLI
mantis ping <url> [--timeout SECONDS] [--header K:V ...] [--log PATH] [--no-log]
Ejemplo:
python -m mantis ping http://127.0.0.1:8000/health
Salida:
200 http://127.0.0.1:8000/health
duration: 12.5 ms
size: 15 bytes

Exit codes:

Código	Significado
0	Éxito
1	Error de red (timeout, connection, DNS)
2	Error de argumentos (header malformado)
3	Rate limit excedido

10. Notas conocidas
10.1 — Starlette deprecation warning
Heredado de MK-002. TestClient emite un warning sobre httpx. No afecta a MK-003. Se resolverá cuando FastAPI actualice.

10.2 — _WindowCounter simple
La ventana deslizante es una lista de timestamps. Para decenas de peticiones (MK-003, MK-004), es suficiente. Si en MK-005/MK-006 se necesita alta concurrencia, se migrará a token bucket.

10.3 — Sin concurrencia
MK-003 es secuencial. Una petición a la vez. Async llegará cuando lo necesite MK-006 (secuencias).
