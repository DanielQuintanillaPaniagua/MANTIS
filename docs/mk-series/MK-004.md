## 1. Objetivo del hito

Permitir que MANTIS **lea una especificación OpenAPI** y la transforme en
un modelo normalizado de operaciones. MK-004 **no envía peticiones HTTP**.
Solo lee archivos locales y produce objetos internos que MK-005 usará.

---

## 2. Alcance: qué SÍ entró

- OpenAPI 3.0.x y 3.1.x.
- Archivos locales `.json`, `.yaml`, `.yml`.
- Extracción de métodos y rutas.
- `operationId`, `summary`, `description`, `tags`.
- Parámetros de path, query, header, cookie.
- **Parámetros heredados** (path → operation, con override por `(name, in)`).
- `requestBody` (required, content types, `$ref` informativo).
- `responses` (códigos, descripciones, content types).
- `servers` globales y por operación.
- **Esquemas de seguridad**: apiKey, http (basic/bearer), oauth2, openIdConnect, mutualTLS.
- **Seguridad global y por operación**, con **semántica AND/OR preservada**.
- **`$ref` internos** (`#/...`) resueltos recursivamente.
- Rechazo explícito de `$ref` externos (URLs, ficheros).
- CLI `mantis spec inspect <file>` con `--json` y `--security`.
- Errores tipados (`SpecError` y subclases).

---

## 3. Fuera de alcance: qué NO entró

- Enviar solicitudes HTTP.
- Detección de vulnerabilidades (MK-005).
- Generación de secuencias (MK-006).
- Autenticación real contra APIs.
- OAuth2 / renovación de tokens.
- Descarga de specs desde URL remotas.
- Resolución de `$ref` externos.
- Validación completa del schema OpenAPI (solo lo que MANTIS usa).
- Dashboard, base de datos de hallazgos, reportes.

**Decisión de seguridad:** MK-004 solo lee archivos locales. No hay
riesgo de SSRF desde el importador.

## 5. Modelo normalizado

### `ApiSpec`

| Campo | Tipo | Descripción |
|---|---|---|
| `openapi_version` | `str` | Ej. `"3.1.0"` |
| `title` | `str` | De `info.title` |
| `version` | `str` | De `info.version` |
| `description` | `str \| None` | De `info.description` |
| `servers` | `tuple[str, ...]` | URLs de servidores |
| `operations` | `tuple[Operation, ...]` | Operaciones extraídas |
| `security_schemes` | `tuple[SecurityScheme, ...]` | Esquemas declarados |

### `Operation`

| Campo | Tipo | Descripción |
|---|---|---|
| `method` | `HttpMethod` | GET, POST, ... |
| `path` | `str` | Ej. `/invoices/{invoice_id}` |
| `operation_id` | `str \| None` | De `operationId` |
| `summary` | `str \| None` | De `summary` |
| `description` | `str \| None` | De `description` |
| `tags` | `tuple[str, ...]` | De `tags` |
| `parameters` | `tuple[Parameter, ...]` | Efectivos (heredados + operación) |
| `request_body` | `RequestBody \| None` | De `requestBody` |
| `responses` | `tuple[Response, ...]` | Ordenadas por código |
| `security` | `tuple[SecurityRequirement, ...]` | **Efectivos** (global o propio) |
| `servers` | `tuple[str, ...]` | **Pendiente:** fusión con global (MK-005) |

### `SecurityRequirement` — la estructura AND/OR

**Regla crítica:**

- La **lista** de `SecurityRequirement` en `Operation.security` es **OR**.
- El **dict** dentro de un `SecurityRequirement.schemes` es **AND**.

Ejemplo:

```yaml
security:
  - OAuth2: [admin]
    MTLS: []
  - ApiKeyAuth: []
```

Se traduce a:

```python
(
    SecurityRequirement(schemes={"OAuth2": ("admin",), "MTLS": ()}),  # OR alternativa 1
    SecurityRequirement(schemes={"ApiKeyAuth": ()}),                  # OR alternativa 2
)
```

- Alternativa 1: `OAuth2` **AND** `MTLS`.
- Alternativa 2: `ApiKeyAuth` sola.

**No aplanar.** MK-005 necesita esta estructura para generar hipótesis correctas.

## 6. Tres reglas OpenAPI que el parser respeta

### 6.1 — Parámetros heredados

Los parámetros definidos a nivel de ruta se combinan con los de la
operación. Si coinciden en `(name, in)`, la **operación reemplaza** a
la ruta. Los parámetros de path siempre son `required: true`.

### 6.2 — Seguridad efectiva

Si una operación declara `security`, **reemplaza** la global, aunque
sea `security: []` (que significa "sin seguridad"). Si no declara
`security`, hereda la global.

**Distinción crítica:**

- `"security" not in raw` → hereda la global.
- `"security" in raw and raw["security"] == []` → opt-out (sin seguridad).

### 6.3 — AND/OR

Preservado. Ver sección 5.

## 7. `$ref`

- **Internos** (`#/components/schemas/Invoice`): resueltos recursivamente.
- **Externos** (`https://...`, `./other.yaml`): rechazados con `SpecReferenceError`.
- **Escapes de JSON Pointer** (`~1` → `/`, `~0` → `~`): soportados.
- **Recursión máxima:** 32 niveles. Ciclos → `SpecReferenceError`.

## 12. Notas conocidas

### 12.1 — `servers` por operación

`Operation.servers` existe en el modelo pero el parser no lo rellena
todavía. Solo se extraen `servers` globales en `ApiSpec.servers`.

**Pendiente para MK-005:** fusionar `servers` globales con `servers`
por operación (con override). La estructura ya está preparada.

### 12.2 — `requestBody.schema_ref` informativo

Si el `$ref` del schema se resuelve antes de extraer `RequestBody`,
`schema_ref` queda `None`. Es aceptable: es un campo informativo.
MK-005 no lo necesita.

### 12.3 — Validación mínima

El parser **valida**:

- `openapi`, `info`, `paths` presentes y del tipo correcto.
- Versión 3.0.x o 3.1.x.
- `info.title` e `info.version` como strings no vacíos.
- `$ref` internos resolubles.

**No valida:**

- Schemas completos.
- `content-type` específicos.
- `callbacks`, `webhooks`, `links`.

Si en MK-005 se necesita más, se añade entonces.

### 12.4 — `servers` del lab están vacíos

FastAPI no añade `servers` a menos que se le indique. `mantis-lab.json`
tiene `servers: []`. No es un error del parser. Si se quiere un lab
con `servers`, se añade en `lab/app.py` o en un fixture adicional.
