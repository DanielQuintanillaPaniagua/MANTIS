## 1. Objetivo

Expandir las capacidades de detección de MANTIS para evaluar APIs con diferentes mecanismos de autenticación, múltiples identidades y operaciones sobre recursos.

## 2. Matriz de autorización multi-identidad

MANTIS acepta un número configurable de identidades (`max_identities`, por defecto 5) y construye una matriz de acceso para cada recurso.

## 3. BOLA en operaciones de escritura

Se amplió la detección para contemplar GET, PUT, PATCH y DELETE.
**Seguridad:** Las operaciones de escritura solo se ejecutan si existe un `reset_endpoint` configurado. Si la restauración falla, el escaneo se aborta con estado `INCONCLUSIVE`.

## 4. Severidad y confianza

Los findings ahora tienen severidad contextual:
- `CRITICAL`: DELETE o fuga de datos sensibles.
- `HIGH`: PUT/PATCH o GET normal.
- `MEDIUM`: Listados sin datos sensibles.

## 5. Estados de evaluación

MANTIS diferencia explícitamente:
- `CONFIRMED`: Vulnerabilidad respaldada por evidencia.
- `NOT_FOUND`: Prueba ejecutada, no encontró vulnerabilidad.
- `OMITTED`: Prueba no ejecutada (ej. falta de reset_endpoint).
- `INCONCLUSIVE`: Evidencia insuficiente o error durante la prueba.

## 6. Validación externa

Se prepararon los scripts (`scripts/validate_external.ps1`) y la documentación (`docs/validation/MK-009-results.md`) para ejecutar MANTIS contra crAPI y VAmPI.
**Estado actual:** Pendiente de ejecución en entorno con Docker.

## 7. Correcciones de la Auditoría (MK-009.1 / MK-009.2)

- **Bloqueante resuelto:** `scan.py` ya no tiene errores de indentación.
- **Integridad de escrituras:** `detect_bola_write` aborta con `INCONCLUSIVE` si falla la restauración.
- **Matriz multi-identidad:** `detect_bfla` y `detect_state_skip` aceptan listas de identidades.
- **Credenciales:** El CLI acepta variables de entorno (`MANTIS_KEY_<NAME>`).
- **Estados engañosos:** El fallback de IDs devuelve `INCONCLUSIVE` si no pudo enumerar recursos.
