## 1. Objetivo del hito

Convertir los hallazgos de MK-005 y MK-006 en **evidencia utilizable**
y permitir **verificar correcciones** a lo largo del tiempo.

MK-007 añade:

- Exportación de findings en **JSON** (para CI/automatización) y
  **Markdown** (para lectura humana).
- **Baselines**: guardar el estado esperado de un scan.
- **Regresión**: comparar un scan actual contra un baseline y detectar
  vulnerabilidades corregidas o nuevas.

**No** detecta nuevas vulnerabilidades. **No** añade tipos de finding.
**Solo** hace que los hallazgos existentes sean **accionables**.

---

## 2. Alcance: qué SÍ entró

- Formateadores `format_findings_json` y `format_findings_markdown`.
- `mantis scan --format {human,json,markdown}`.
- `mantis scan --save-baseline <file>`: guarda los findings esperados.
- `mantis regression run <baseline>`: re-ejecuta y compara.
- Baseline **sin API keys** (las identidades se guardan por nombre).
- Detección de findings **corregidos**, **nuevos** y **pendientes**.
- Exit codes diferenciados.

---

## 3. Fuera de alcance: qué NO entró

- Base de datos de findings.
- Dashboard web.
- Exportación a PDF, HTML, CSV.
- Envío a Slack / email / Jira.
- Generación automática de fixes.
- Detección de nuevas vulnerabilidades.
- Comparación semántica de findings (solo por ID).

## 5. Formatos de salida

### 5.1 — JSON

```json
{
  "spec": "MANTIS Lab",
  "findings_count": 5,
  "findings": [
    {
      "id": "BOLA-_invoices_{invoice_id}-3",
      "type": "BOLA",
      "severity": "high",
      "confidence": "high",
      "operation_method": "GET",
      "operation_path": "/invoices/{invoice_id}",
      "identity": "employee",
      "summary": "...",
      "details": "...",
      "evidence": [...],
      "reproduction": [...]
    },
    ...
  ]
}
```

**Uso:** CI, scripts, comparación automatizada.

### 5.2 — Markdown

```markdown
# MANTIS Scan Report: MANTIS Lab

**Findings:** 5

## Summary

| ID | Type | Severity | Confidence | Operation | Identity |
|---|---|---|---|---|---|
| BOLA-... | BOLA | high | high | GET /invoices/... | employee |
...

## Details

### BOLA-_invoices_{invoice_id}-3

- **Type:** BOLA
- **Severity:** high
...

**Evidence:**
- admin reads resource 3
  - `GET http://127.0.0.1:8000/invoices/3` → 200
...

**Reproduction:**
1. Use identity 'employee'
2. GET http://127.0.0.1:8000/invoices/3
3. Expected 403, got 200
```

**Uso:** leer en GitHub, adjuntar a PRs, pegar en issues.

### 5.3 — Human (default)

Salida de texto sin formato. Es la que ya existía. Útil para terminal.

## 6. Baseline

Formato del fichero de baseline:

```json
{
  "spec": "examples/openapi/mantis-lab.json",
  "spec_title": "MANTIS Lab",
  "options": {
    "sequences": true,
    "privileged_operations": ["approve"],
    "allowed_transitions": [
      "status:draft->submitted",
      "status:submitted->approved"
    ],
    "max_requests": 200,
    "base_url": "http://127.0.0.1:8000"
  },
  "identities": [
    {"name": "admin"},
    {"name": "employee"}
  ],
  "expected_findings": [
    {"id": "BOLA-_invoices_{invoice_id}-3", "type": "BOLA"},
    {"id": "BOLA-_invoices_{invoice_id}-4", "type": "BOLA"},
    {"id": "BFLA-_invoices_{invoice_id}_approve-1", "type": "BFLA"},
    {"id": "BFLA-_invoices_{invoice_id}_approve-2", "type": "BFLA"},
    {"id": "STATE_SKIP-_invoices_{invoice_id}_approve-1", "type": "STATE_SKIP"}
  ]
}
```

**Sin API keys.** Las identidades se guardan por nombre. Las keys
se pasan por CLI al hacer `regression run`.

Puede commitearse al repositorio. Es determinista y no contiene
secretos.

## 7. Regresión

```text
mantis regression run <baseline> --identity A:key --identity B:key [--format human|json|markdown]
```

**Salida humana:**

```text
MANTIS :: REGRESSION

Spec: examples/openapi/mantis-lab.json
Spec title: MANTIS Lab
Expected findings: 5
Actual findings: 5

Still present (5):
  [OK] BOLA-_invoices_{invoice_id}-3
  [OK] BOLA-_invoices_{invoice_id}-4
  [OK] BFLA-_invoices_{invoice_id}_approve-1
  [OK] BFLA-_invoices_{invoice_id}_approve-2
  [OK] STATE_SKIP-_invoices_{invoice_id}_approve-1

Verdict: EXPECTED (all present, 0 new)
```

**Escenario con corrección:**

```text
Corrected (2):
  [FIXED] BOLA-_invoices_{invoice_id}-3  (no longer detected)
  [FIXED] BOLA-_invoices_{invoice_id}-4  (no longer detected)

Verdict: CHANGED (2 corrected, 0 new)
```

**Exit codes:**

| Código | Significado |
|---|---|
| 0 | Todo como se esperaba (todos presentes, 0 nuevos) |
| 1 | Hay cambios (corregidos o nuevos) |
| 2 | Error de argumentos |
| 3 | Rate limit |
| 4 | Error de spec o baseline |
| 5 | Error de escritura de log |

## 8. Flujo de uso

### 8.1 — Primera ejecución (baseline)

```bash
mantis scan examples/openapi/mantis-lab.json \
    --identity admin:lab-admin-key \
    --identity employee:lab-employee-key \
    --sequences \
    --privileged-operations approve \
    --allowed-transition "status:draft->submitted" \
    --allowed-transition "status:submitted->approved" \
    --max-requests 200 \
    --save-baseline baselines/lab.json \
    --format markdown > report.md
```

### 8.2 — Verificación en CI

```bash
mantis regression run baselines/lab.json \
    --identity admin:lab-admin-key \
    --identity employee:lab-employee-key \
    --format json > regression.json
```

Si exit code 0, todo como se esperaba. Si 1, hay cambios.

### 8.3 — Tras corregir una vulnerabilidad

El finding desaparece de `actual`. `regression` lo marca como `corrected`
y exit 1. El operador actualiza el baseline (elimina el finding
corregido). La siguiente ejecución da exit 0.

## 12. Notas conocidas

### 12.1 — Comparación por ID, no por contenido

`regression` compara findings por `id`. Si dos findings tienen el mismo
ID pero contenido distinto (ej. `details` cambió), no se detecta. Es
suficiente para MK-007. Comparación semántica queda para hitos posteriores.

### 12.2 — Baseline manual tras corrección

Tras corregir una vulnerabilidad, el baseline debe actualizarse
manualmente (eliminar el finding corregido). No hay auto-actualización
del baseline. Es intencional: el operador decide cuándo aceptar un
cambio.

### 12.3 — Salida ASCII en Windows

Los caracteres ✓, ✓✓, ⚠ se reemplazaron por `[OK]`, `[FIXED]`,
`[NEW]` para compatibilidad con consolas Windows (CP1252). En Linux/Mac
se podrían usar los símbolos originales, pero ASCII es portable.

### 12.4 — `--json` deprecated en `scan`

`mantis scan --json` sigue funcionando como alias de `--format json`.
Pero está deprecated. Nuevos usos deben usar `--format json`.
